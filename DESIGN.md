## Brand & Style

This design system embodies the agile, vibrant, and developer-first spirit of Zenika Training. The product serves IT professionals, tech leads, engineering managers, and corporate learners seeking hands-on mastery in modern architecture, cloud technologies, DevOps, front-end ecosystems, and agile leadership.

The aesthetic blends **Modern Tech Minimalism** with an energetic, pedagogical edge:
- **Clean and Pragmatic:** Generous whitespace, precise typographic hierarchies, and minimal visual noise ensure complex technical learning paths remain intuitive and digestible.
- **Dynamic Energy:** Zenika’s iconic energetic red is paired with crisp multi-color topic categorizations (tech blue, architecture violet, agile orange, and code mint), injecting life and clarity into course cards and track overviews.
- **Approachable Craft:** Soft pill elements, clean borders, and subtle elevation create an inviting, human, yet uncompromisingly technical learning environment.

## Colors

The color palette centers on Zenika’s signature red, accented by functional category colors mapped to course tracks and technical domains. Every text/background pair below meets WCAG 2.1 AA (RGAA 3.2); the exact ratios are in [Accessibility](#accessibility-rgaa-4--wcag-21-aa).

- **Brand red (`#EE1D23`, `zenika-red-brand`):** Decorative and graphical use only (logo, accent rules, illustrations). White text on it is 4.34:1, which fails AA for normal text: never put text on this red.
- **Action red (`#BB0012`, `action-primary`, hover `#93000B`):** Solid backgrounds for primary calls-to-action (white text, 6.73:1 and 9.35:1). As text on light surfaces use `#C8101E` (`zenika-red-dark`, 5.62:1 on the canvas).
- **Secondary (`#0058BE`):** Interactive links and technical status highlights. `#3B82F6` is a decorative accent only (3.38:1 on its tint).
- **Tertiary (`#712AE2`):** Advanced specialization paths, certifications, and masterclasses.
- **Functional Category Accents (`named_colors`):**
  - `track-tech-blue` (`#3B82F6`) and `track-cloud-cyan` (`#06B6D4`): Infrastructure, containers, and web standards.
  - `track-agile-orange` (`#F97316`): Agility, product management, and team collaboration.
  - `track-code-mint` (`#10B981`): Developer sessions, test automation, and code-lab guarantees.
  - `track-archi-purple` (`#8B5CF6`): Architecture, data engineering, and AI.
  - These saturated accents are for graphics, rules and illustrations. **Text** in a track color uses the darker `badge-*-fg` tokens (see Badges).
- **Neutrals:**
  - Base canvas: Off-white snow surface (`#F8F9FC`).
  - Elevated containers: Pure white (`#FFFFFF`).
  - Typography: Deep charcoal slate (`#111827` and `#1E293B`), 16.85:1 on the canvas (AAA). Secondary text is `#5B6B82` (`text-muted`, 5.15:1): never lighter.
  - Hairline borders (`#E2E8F0`, `#CBD5E1`) are **decorative separators only** (1.2:1 to 1.5:1). Anything the user must locate to operate (inputs, selects, toggles) uses `control-border` (`#7C8DA3`, ≥ 3:1).
- **Color is never the only carrier of information** (RGAA 3.1): topic, state and selection always carry a text label or a shape change in addition to the color.

## Themes (light, dark, system)

Three modes: **System** (default, follows `prefers-color-scheme`), **Light**, **Dark**; the interface exposes light/dark only, and "System" is the state when nothing is stored. The user choice is stored in the browser and never required; the switch (see Theme Switch) toggles between light and dark. Light values are the tokens above; dark values are the `dark-*` tokens, derived from the `inverse-*` tokens.

| Role | Light | Dark |
| --- | --- | --- |
| Canvas | `#F8F9FC` | `#0F1726` |
| Card | `#FFFFFF` | `#1A2438` |
| Text | `#111827` | `#ECF1FF` |
| Muted text | `#5B6B82` | `#B4BFD3` |
| Decorative border | `#E2E8F0` | `#34425A` |
| Control border | `#7C8DA3` | `#8A98B0` |
| Red as text | `#C8101E` / `#BB0012` | `#FFB4AB` |
| Primary button | `#BB0012` (hover `#93000B`), white label | `#C8101E` (hover `#E7151F`), white label |
| Focus ring | `#111827` | `#FFFFFF` |

Implementation: CSS custom properties with `light-dark()` and `color-scheme`; an explicit user choice sets `data-theme="light|dark"` on `<html>`. The choice is applied by an inline script in `<head>` before first paint, so there is no flash. Without JavaScript the page follows the system.

## Typography

The type scale combines **Plus Jakarta Sans** for expressive, geometric headers and navigation items with **Inter** for dense, ultra-readable body content, syllabi, prerequisites, and code references.

- **Plus Jakarta Sans** provides a forward-leaning, friendly, yet authoritative presence across hero headlines and track badges. Tighter tracking (-0.02em) is applied to all titles above 26px.
- **Inter** ensures maximum legibility for lengthy pedagogical descriptions, course curricula lists, and instructional specifications.
- **Accessibility rules:** sizes in `rem` so the browser text-size setting applies; the layout must stay usable at 200% zoom (RGAA 10.4) and with the WCAG text-spacing overrides: line-height 1.5, paragraph spacing 2x, letter-spacing 0.12em, word-spacing 0.16em (RGAA 10.12). Body line-height is never below 1.5. Minimum text size is 12px (badges only); body copy is 15px or more. Web fonts load with `font-display: swap` and fall back to `system-ui`, so text stays readable if the font fails or is blocked.
- **Monospace & Code Snippets:** Code terms, CLI instructions, and module IDs inherit `code-sm` using a tabular, neutral rendering.

## Layout & Spacing

The layout operates on a standard responsive 12-column grid capped at a maximum width of `1280px` (`80rem`), centered on viewports wider than desktop breakpoints.

- **Desktop (1024px+):** 12-column grid with `1.5rem` (`24px`) gutters and `2rem` (`32px`) page margins. Catalog grids default to 3 columns; training dashboards shift to asymmetrical 8:4 splits.
- **Tablet (768px – 1023px):** 8-column layout with `1.25rem` gutters. Course grids switch to 2 columns.
- **Mobile (< 768px):** 4-column layout with `1rem` gutters and `1.25rem` margins. Course cards, track selectors, and metadata stack vertically.
- **Reflow (RGAA 10.11):** no horizontal scrolling down to a 320px viewport (and at 400% zoom); content never depends on a fixed width. Hit targets are at least `target-min` (36px) high and never closer than 8px; primary controls on touch devices use `target-comfortable` (44px).
- **Rhythm:** Spacing follows an 8px base scale. Inner card padding maintains `space-lg` (`1.5rem`), while section breaks scale from `space-xl` on mobile to `space-2xl` on desktop.

## Elevation & Depth

Visual depth is achieved through **low-contrast architectural outlines and subtle ambient tinted shadows**, avoiding heavy skeuomorphic effects.

- **Surface Tier 0 (Canvas):** `#F8F9FC` serves as the foundation.
- **Surface Tier 1 (Cards & Sidebars):** `#FFFFFF` surfaces bounded by a 1px hairline stroke in `#E2E8F0`. Elevation uses an extra-diffuse ambient shadow: `0 4px 20px -2px rgba(17, 24, 39, 0.05)`.
- **Surface Tier 2 (Floating Popovers, Search Drawers, Sticky Enrollment Bars):** `#FFFFFF` bordered with `0 12px 32px -4px rgba(17, 24, 39, 0.10)`.
- **Card Hover Elevation:** On hover, course cards translate upward by `-2px`, and the border color shifts toward `#CBD5E1` accompanied by an expanded shadow `0 12px 28px -6px rgba(17, 24, 39, 0.08)`. Hover is an enhancement: the same feedback is given on keyboard focus, and nothing is revealed only on hover (RGAA 10.13).
- **Motion:** transitions last 150ms or less and are removed under `prefers-reduced-motion: reduce` (no translate, no scale, no rotation). No autoplay, blinking or looping animation (RGAA 13.8).

## Shapes

The interface balances friendly pill curvature for interactive markers with generous rounded geometry for architectural surfaces:

- **Pill Shape (`rounded-full` / `9999px`):** Used universally across all actionable buttons, training topic badges, session duration tags (e.g., "3 jours / 21h"), modality pills ("À distance", "Présentiel"), and notification counters.
- **Container Surfaces (`rounded-xl` / `1rem` to `1.5rem`):** Used on course cards, curriculum modules, speaker callouts, and search input wraps.
- **Form Controls & Tables (`rounded-md` / `0.5rem`):** Used for filter toggles, calendar pickers, and code preview containers.

## Components

### Buttons
- **Primary Action (Inscription / Devis):** Full pill (`rounded-full`), solid `action-primary` (`#BB0012`) background with white text, font weight 600. Hover: `action-primary-hover` (`#93000B`). The brand red `#EE1D23` is not used as a text background (4.34:1). No scale effect.
- **Secondary Action (Découvrir le programme):** Pill shape, transparent background with 1.5px border in `#1E293B`, dark slate label text. Hover and keyboard focus: `#1E293B` background with `#FFFFFF` text.
- **Ghost / Link:** Text in `#C8101E` or `#0058BE` with an arrow that slides on hover (not under reduced motion). Links inside text are underlined (RGAA 10.6); the link text alone must make sense out of context (RGAA 6.1).
- **Opening a new tab:** state it in the accessible name ("(nouvel onglet)"), visually hidden if an icon already shows it, and use `rel="noopener"` (RGAA 6.2).
- **Icon-only buttons** have an accessible name; an icon never replaces a label for the primary actions.

### Badges & Chips
- **Topic Badges:** Full pill with a lightweight tinted background and a text label (never color alone). Text colors are the `badge-*-fg` tokens, darkened from the saturated accents to reach 4.5:1:
  - *Cloud / DevOps:* `#1D4ED8` on `#EFF6FF`.
  - *Agile / Product:* `#C2410C` on `#FFF7ED`.
  - *Web / Craft:* `#047857` on `#ECFDF5`.
  - *Data / AI:* `#6D28D9` on `#F5F3FF`.
  - *Unclassified:* `text-muted` on the canvas with a hairline border.
  - Dark theme: the `dark-badge-*` tokens (light tint on a deep tint).
- **Certification Marker:** Pill badge featuring a subtle golden or colored dot prefix to denote Qualiopi or official vendor accreditation. The dot is decorative: the text states the accreditation.

### Course Cards
- **Base Style:** Solid `#FFFFFF` container with `rounded-xl` (16px) corners and a 1px border (`#E2E8F0`).
- **Structure:**
  - Header: Topic chip and next available session date ("Prochaine session: 14 Nov").
  - Title: `headline-md` in `#111827`, a real heading (`h2`). Titles wrap and are never truncated (RGAA 10.12).
  - Body: 2-line summary in `body-sm` (`#5B6B82`), only if the full text is available on the destination page.
  - Footer: Divider line, duration badge, course rating with star indicator, and primary action button or arrow link. A rating always has a text value ("4,6 sur 5"), never stars alone.
- **Whole card is one link:** a single focus stop per card, named by its title and action. Do not nest other links or buttons inside it. The list of cards is a real `ul` (RGAA 9.3).
- **Focus:** visible 3px ring in `focus-ring` with a 3px offset, on the card and on its action (RGAA 10.7).

### Header
- **Bar:** `surface-card` background with a hairline bottom edge and a diffuse shadow, content on the 80rem grid. Left: the official Zenika Training logo (SVG from https://training.zenika.com/fr, inlined, 44px high); the wordmark takes `currentColor` so it follows the theme, the red gradient disc and its white glyph never change. The logo is decorative (`aria-hidden`) and the link carries the name "Zenika Training, accueil". Right: the theme switch. The search is not in the bar (see Form Inputs & Search).
- **Hero:** under the bar, a vertical gradient from `hero` (`#F1EEFF` light, `#1A1F3D` dark) to the canvas; centered `headline-hero` title (-0.04em tracking) and a `body-lg` lead in `text-muted` (4.76:1 on `#F1EEFF`). Purely decorative shapes, if any, are `aria-hidden` and never carry text.
- **Logo:** keep the proportions (170:60), never recolor the disc, leave clear space of at least half the disc height around it. Contrast: the wordmark uses `text` (16.85:1 light, 15.88:1 dark).

### Form Inputs & Search
- **Training Search Bar:** Pill or `rounded-xl` enclosure with `#FFFFFF` background, a `control-border` (`#7C8DA3`) 1.5px border, `1rem` horizontal padding, magnifying glass icon (decorative, `aria-hidden`) in `#5B6B82`, and placeholder "Rechercher une formation (ex: Docker, Kubernetes, Angular, Spring...)" in `Inter 15px`.
- **Placement:** in the page body, centered under the hero, above the result count ("N formations disponibles") and the grid, up to 40rem wide.
- **Filled variant:** filled pill, `search-bg` (`#111827` light, `#ECF1FF` dark) with `search-fg` text and icon, placeholder `search-hint` (11.95:1 / 9.17:1). It is wrapped in `role="search"`. The focus ring keeps the 3px offset so it stays visible against the filled pill.
- **Label (RGAA 11.1):** every field has a programmatically associated `<label>` (visually hidden only when the placeholder repeats it). A placeholder is a hint, never the only label. Use `type="search"`.
- **Results feedback (RGAA 7.5):** the result count sits in a `role="status"` live region ("3 formations trouvées"), and an empty result shows a text message, not just a blank grid. Filtering works while typing and by keyboard only.
- **Checkboxes & Radios:** `rounded-md` (4px) for checkboxes, circular for radios, at least 24px. In checked state, filled with `action-primary` with a crisp white checkmark icon; the checked state also changes shape (the checkmark), not only color.

### Theme Switch
Secondary control, deliberately discreet: it lives at the end of the header, never in the hero.
- **Form:** a sliding switch (pill track, round knob) with a sun icon on the left and a moon icon on the right. It is a `<button role="switch">` with `aria-checked` (true = dark) and the accessible name "Mode sombre"; the icons are decorative (`aria-hidden`).
- **Style:** track 76×40px (≥ `target-min`), `card` background, `control-border` 1.5px. The knob (`knob`: white in light, `#34425A` in dark) has its own `control-border` outline so its position reads at ≥ 3:1. The icon on the active side is colored (sun `#B45309`/`#FCD34D`, moon `#4F46E5`/`#C4B5FD`, ≥ 5:1 on the knob), the other is `text-muted`. State is never carried by color alone: the knob position says it too. Not primary red, not a filled style.
- **Behavior:** the initial state reflects the system theme. A click switches to the opposite theme and stores it in the browser (`localStorage`, failures ignored). Choosing the theme the system already gives clears the stored choice, so the page follows the system again. The knob slides in 150ms (none under `prefers-reduced-motion`). Hidden without JavaScript (the page follows the system).
- **Keyboard:** focusable, toggled with Space and Enter, standard focus ring.

### Accordion / Module List (Program Detail)
- Nested syllabus container with `#FFFFFF` background. Left border of active day highlighted in `#EE1D23`. Each header is a `<button>` with `aria-expanded` and `aria-controls`; the expansion icon rotates (`180deg`) on open (not under reduced motion) and the state is also conveyed by the icon shape.

## Accessibility (RGAA 4 / WCAG 2.1 AA)

Target level: **RGAA 4.x, AA** (equivalent to WCAG 2.1 AA), with WCAG 2.2 AA additions as good practice. This file states the design rules that make conformance possible; actual conformance is only established by an audit of the built pages and published in an *déclaration d'accessibilité*.

### Rules

| Topic | Rule | RGAA |
| --- | --- | --- |
| Text contrast | ≥ 4.5:1 (≥ 3:1 for text of 24px+, or 19px+ bold) | 3.2 |
| UI component and graphic contrast | Borders of inputs/selects, focus ring, icons that carry meaning: ≥ 3:1 | 3.3 |
| Color alone | Never the only carrier of information; always a label, shape or text | 3.1 |
| Focus | Always visible (3px ring, ≥ 3:1 against both the element and the background), never removed with `outline: none` without a replacement; logical tab order | 10.7, 12.8 |
| Keyboard | Everything usable with the keyboard alone; no keyboard trap; a visible focus indicator on every stop | 7.3, 12.x |
| Zoom and reflow | 200% text zoom without loss; no horizontal scroll at 320px | 10.4, 10.11 |
| Text spacing | No loss of content with WCAG text-spacing overrides | 10.12 |
| Hover/focus content | Dismissible, hoverable, persistent; nothing available only on hover | 10.13 |
| Motion | `prefers-reduced-motion` respected; no autoplay or blinking | 13.8 |
| Structure | One `h1`, headings in order, landmarks (`header`, `main`), real lists | 9.1, 9.2, 9.3 |
| Page basics | `lang="fr"`, a unique descriptive `<title>`, valid HTML; `lang` on passages in another language | 8.2, 8.3, 8.5, 8.7 |
| Links | Explicit name out of context; new tab announced | 6.1, 6.2 |
| Forms | Associated labels, visible or hidden, placeholder never alone | 11.1 |
| Dynamic updates | Status messages in `role="status"` / `aria-live="polite"` | 7.5 |
| Images and icons | Decorative icons `aria-hidden`; informative ones have a text alternative | 1.2, 1.3 |
| Scripts | The page remains usable and readable without JavaScript; scripts are assistive-technology friendly | 7.1 |

### Review checklist
1. Run the page in both themes and check every text pair against the table above.
2. Tab through the page: focus is visible, the order is logical, nothing traps focus.
3. Zoom to 200% and resize to 320px: no loss, no horizontal scroll.
4. Apply the text-spacing bookmarklet: nothing is clipped or overlapping.
5. Turn on `prefers-reduced-motion`: no movement remains.
6. Test with a screen reader (VoiceOver or NVDA): headings, list of links, search results announcement, theme switch name and state.
7. Validate the HTML (RGAA 8.2) and run an automated check (axe, Asqatasun), then complete with the manual RGAA checklist.
